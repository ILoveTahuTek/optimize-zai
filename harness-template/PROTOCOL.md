# PPC Loop Protocol v1.1 — Propose · Probe · Compose

Harness-agnostic quality loop for LLM agents. It improves **the harness** — everything
around the model: instructions, skills, scripts, tool configs, output contracts — never
the model weights. Derived from Google Research's Harness² (Apache-2.0, arXiv:2610.14224)
and validated end-to-end on a 3-task data-report experiment (13 solver rollouts, ~480k
subagent tokens): task 1 audit 5/8 → 8/8, unseen-data transfer 8/10 → 10/10, task 3
k=2 pool base 8/10 → five harnesses 10/10. Every gain came from harness edits alone.

**Harness-agnostic** means: any agent runtime that can (a) spawn a stateless
sub-executor and (b) read/write files can run this protocol. No vendor SDK, no API keys;
the tooling below is Python stdlib only.

## 0. When to run the loop

Run it when ALL of these hold:

- the task produces an artifact with checkable structure (report, analysis, code output);
- the domain repeats or will repeat (a library entry will pay off);
- solver runs can be isolated (fresh subagent/sandbox per rollout).

Skip it for: one-shot edits, pure conversation, tasks whose outputs cannot be compared.

Cost tiers:

| Tier | When | Shape |
|---|---|---|
| T0 single-pass | trivial, or first-time throwaway | no loop |
| T1 k=1 | cheap but repeated domain | base → 1 candidate → compose → select |
| T2 k≥2 parallel | high-stakes / dirty data | base → 2k candidates → 2 compositions → blind select |

## 1. Roles (names are roles, not identities)

| Role | Filled by | Hard constraint |
|---|---|---|
| SOLVER | stateless sub-executor, model pinned | sees ONLY the harness tree + input dir; no chat history, no memory across rollouts |
| PROPOSER | main agent | every candidate maps ≥1 observed defect to a named mechanism; at T2 emit ≥1 generic + ≥1 domain-specific candidate |
| PROBER | sandbox | smoke-test every script on synthetic mini-data BEFORE probing; one fresh sandbox per candidate |
| COMPOSER | main agent | merges surviving edits; result must run in a fresh sandbox untouched |
| SELECTOR | main agent, or a second-opinion subagent | blind: no harness names, no source paths, identical report schema |
| AUDITOR | main agent | opens sealed ground truth only AFTER ranking is written |

## 2. File contract (one task)

Created by `scripts/new_lab.py`:

```
<lab>/<domain>/tasks/<task>/
  input/                      # exactly what the solver receives — nothing else leaks in
  harnesses/
    base/                     # current adopted harness: INSTRUCTIONS.md [+ skills/ + scripts/]
    candidates/cand-<id>/     # candidate trees: full copies, each runnable as-is
    composed/                 # merged harness (T2: composed-a/, composed-b/, ...)
  runs/<harness>/             # report.md + process.md + whatever the solver produced
  selection/
    blind/RUN-<X>.report.md   # anonymized copies, one identical schema
    key.json                  # strict JSON by blind_reports.py — DO NOT open before ranking exists
    ranking.md                # blind ranking + rationale; written BEFORE key.json is opened
  audit/
    checklist.json            # sealed scoring rubric (ids + weights)
    answers.json              # per-harness check results (post-selection only)
    scores.md                 # generated by score_audit.py
```

Domain library (the level-2 recursion):

```
<lab>/library/<domain>/
  INDEX.md                        # one row per adopted harness: name, components, cue
  harnesses/<task>/harness/       # FULL adopted tree, runnable as-is
  harnesses/<task>/EXPERIENCE.md  # cue / lesson / evidence / confidence / components
```

## 3. The loop

0. **MIGRATE** — if `library/<domain>/INDEX.md` exists, adopt its newest harness verbatim
   as `base/` and note the adoption in the base rollout header.
1. **BASE ROLLOUT** — SOLVER runs the base harness on `input/` → `runs/base/report.md`.
2. **DEFECT SCAN** — one line per defect with verbatim evidence: mislabels, contradicting
   numbers, silent data drops, unverifiable claims, missing disclosure.
3. **PROPOSE** — k candidates. Each is a full runnable tree plus a proposal block:
   defects targeted → mechanisms. Generic levers: written definitions, dual verification,
   explicit output contract. Domain levers: deterministic scripts, anomaly inventories,
   assumptions catalogs.
4. **PROBE** — smoke-test scripts on synthetic mini-data; run each candidate in a fresh
   sandbox. A candidate that cannot run is rejected *with reason* — that is a harness
   defect, not noise (the relative-path defect was caught exactly this way, twice).
5. **COMPOSE** — merge surviving non-conflicting edits, then a SELF-CONTAINMENT CHECK:
   no references outside the tree, all internal paths absolute (or inline), scripts run
   in a fresh sandbox.
6. **SELECT** — `blind_reports.py` → write `ranking.md` → only then open `key.json`.
7. **AUDIT** — `score_audit.py` against the sealed checklist; score the base too, for the
   delta. Audit results never flow back into candidates mid-loop.
8. **PERSIST** — if the winner ≠ base: `write_library_entry.py` with cue / lesson /
   evidence / confidence.
9. **NEXT** — the next task in the same domain starts from the library harness; re-run
   the loop only for NEW defect classes (otherwise accept T0).

## 4. Rules (each paid for itself in the validation experiment)

1. Evidence is behavioral contrast: same input, different harness, different output.
   Opinions about prompts are not evidence.
2. A harness must be self-contained: absolute paths, assets inside the tree, zero reliance
   on session memory. Relatively-referenced skill files were lost by solvers 3 of 4 times
   even though the files existed.
3. Smoke-test scripts on synthetic data before any probe; a broken probe is information.
4. Ground truth stays sealed OUTSIDE the lab tree until `ranking.md` exists.
5. Selection keys are strict JSON (never `repr()`); the selector never sees names, paths,
   or provenance.
6. Blind reports share one identical schema; a run-dir path inside report text leaks the
   label — scrub it (`blind_reports.py --scrub`).
7. Never tune candidates on ground truth; audit is post-selection only.
8. Every adopted edit cites its mechanism and its evidence; no mechanism, no adoption.
9. Library entries carry confidence; promote on transfer wins, demote on regressions.
10. Correctness saturates fast. What the harness buys is STRUCTURAL guarantees
    (verification, definitions, disclosure), not better luck — pick the tier accordingly.
11. An adoption gap is not authorization. "No harness in the Library for this domain"
    is a finding to report, not a license to pick a stack. Propose 2–3 oracle options
    (what runs the checks, what infra each needs) and wait for the user's pick BEFORE
    installing toolchains, databases, or touching sudo. Prefer the lightest oracle that
    still yields real behavioral evidence (in-process tests, SQLite over a DB server,
    stdlib over new deps). An audit-trail entry documents a decision — it never grants
    authorization: log unconfirmed choices as `assumption → awaiting confirmation`, and
    every logged decision must point to a file that actually exists.

## 5. Experience entry schema (EXPERIENCE.md)

```yaml
cue: <one line — when to reach for this harness>
lesson: <what the harness now guarantees that it did not before>
evidence: <contrast: "base said X (defect), adopted said Y (verified)">
confidence: high|medium|low (or 0..1)
components: <file → change → observed, one block per edit>
```

## 6. Tooling (stdlib-only, in `scripts/`)

| Script | Purpose |
|---|---|
| `new_lab.py` | instantiate the file contract for one task (optionally adopt a library harness) |
| `blind_reports.py` | anonymize + scrub labels + `key.json` (strict JSON, seedable) |
| `score_audit.py` | weighted checklist scoring → `scores.md` |
| `write_library_entry.py` | promote the winner → library tree + INDEX.md + EXPERIENCE.md |

## 7. Provenance

- Method: Harness² — Google Research, Apache-2.0, arXiv:2610.14224. Task-level recursion =
  Propose–Probe–Compose on behavioral-contrast evidence; harnessing-level recursion =
  persistent per-domain library of adopted harnesses + experience.
- Validation lab (full evidence): `harness-lab/` in the same repository that ships this
  template; written report: `download/RESULT-harness2-experiment.md`.
- v1.1: rule 11 added (adoption gap ≠ authorization) after a real failure: an agent with
  no backend harness in the library assumed Rust + local Postgres and planned system
  installs without user confirmation; the environment had no passwordless sudo and no
  toolchain, and the claimed audit-trail entry did not exist.
